# 装修设计 Agent MVP 设计规格

## 1. 产品定位

本 MVP 是一个面向 C 端业主的 AI 装修设计师 Agent Web App。

产品帮助装修小白在装修前回答两个问题：

- 我家适合怎么装？
- 我怎么把自己的想法清楚地讲给设计师或装修公司？

用户上传户型图，选择预设装修风格和预算档位，再用自然语言补充偏好；设计师 Agent 先分析户型，再根据实际情况追问和给建议，最后生成一份包含重点空间效果图、图文解释和 PDF 方案书的装修设计 brief。

MVP 不定位为 CAD 工具、施工图工具、精确报价系统、采购系统或 3D 漫游产品。它的核心价值是快速形成设计方向，帮助业主理解自己的需求，并生成可发给设计师或装修公司的沟通材料。

## 2. 目标用户

目标用户是准备装修的 C 端业主。

他们可能有一些模糊偏好，例如“原木风”“中古风”“显大”“好打理”“不要太网红”，但通常不知道如何把这些偏好转化成布局、材质、配色、家具和可沟通的设计需求。

产品体验应该像在和一位实用型设计师沟通，而不是填写长问卷或操作专业软件。

## 3. MVP 用户流程

### 3.1 上传户型图

用户进入 Web App 后先上传户型图。系统提示用户上传清晰、带房间标注或尺寸信息的图片。

上传后，系统做轻量户型理解，并展示给用户确认：

- 识别到的主要空间
- 可见的房间标注
- 大致空间关系
- 可能存在的采光、动线、收纳或布局问题
- 不确定、需要用户确认的信息

用户可以确认或修正分析结果。

### 3.2 选择风格和预算档位

用户选择一个预设风格作为起点，例如：

- 原木风
- 中古风
- 现代简约
- 奶油风
- 侘寂风

用户同时选择一个预算档位：

- 经济型
- 品质型
- 高品质型

预算档位用于约束材料、家具、定制柜、软装和设计取舍，不输出精确报价。

用户可以再补充自然语言需求，例如：

> 希望显大、好打理，适合一家三口，喜欢原木风，但不要太日式，也不要太网红。

### 3.3 设计师 Agent 追问与建议

Agent 根据户型图、风格、预算档位和用户自然语言需求动态决定追问内容。

追问数量根据实际情况而定，最多 12 个。如果信息已经足够，Agent 不强行问满，直接进入方案生成。

追问应优先围绕会明显影响方案质量的问题，例如：

- 采光与开放感
- 收纳取舍
- 家庭成员与生活习惯
- 做饭频率
- 是否接受开放式布局
- 主卧是否需要梳妆区或办公区
- 第三个重点空间应优先优化厨房、儿童房、书房、卫生间还是其它空间

Agent 可以给出专业建议，并询问用户是否采纳。

示例：

> 客餐厅采光主要集中在阳台一侧。我建议减少深色大体量柜体，优先保留开放感。你是否愿意采纳这个方向？

用户可以选择采纳、拒绝或补充说明。

### 3.4 生成设计方案

需求足够后，系统生成结构化设计方案。

MVP 默认覆盖 2-3 个重点空间：

- 默认包含客餐厅
- 默认包含主卧
- 第三个重点空间由 Agent 根据户型和用户需求选择

每个重点空间包含：

- 一张装修效果图
- 设计目标
- 小白能看懂的设计解释
- 布局建议
- 配色与材质方向
- 家具和软装方向
- 预算档位下的取舍
- 落地注意事项或风险

### 3.5 导出 PDF Brief

最终输出是一份可发给设计师或装修公司的 PDF 方案书。

PDF 包含：

- 用户上传的户型图
- 户型分析摘要
- 用户需求和已采纳建议
- 风格与预算档位
- 整体设计策略
- 重点空间效果图
- 重点空间图文说明
- 预算档位假设与取舍说明
- 免责声明：该文件是装修前沟通 brief，不是施工图或正式报价单

## 4. 推荐产品路线

MVP 采用“设计 brief 优先，效果图辅助”的路线。

产品不应被定位成“上传户型图，生成几张好看的泛装修图”。核心价值应该是 Agent 看起来理解用户的户型和需求，会追问关键问题，并能生成一份设计师可读的 brief。

效果图负责提供视觉冲击和理解成本更低的表达；图文解释负责建立信任，并帮助用户与线下专业人员沟通。

## 5. 核心模块

### 5.1 项目与户型上传模块

为每套房子创建一个设计项目，上传并保存原始户型图，管理项目当前状态和生成进度。

### 5.2 户型理解模块

使用视觉模型输出轻量结构化分析：

- 房间列表
- 可见标注
- 空间关系
- 可能的采光、动线、收纳或布局问题
- 置信度
- 用户修正内容

MVP 不宣称 CAD 级准确度。不确定的信息必须明确标注，并让用户确认。

### 5.3 设计师 Agent 工作流

Agent 采用阶段式工作流，而不是完全自由行动的 Agent。

推荐阶段：

1. 分析户型摘要
2. 读取风格、预算档位和用户偏好
3. 生成针对性追问或建议
4. 根据用户回答更新需求画像
5. 判断是否需要继续追问
6. 生成结构化设计方案

Agent 维护一份需求画像，包含：

- 居住成员
- 生活方式与习惯
- 审美偏好
- 硬性约束
- 预算档位
- 已采纳或拒绝的建议
- 重点空间
- 已知不确定项

### 5.4 方案生成模块

生成整体设计策略和重点空间方案。

同时为每个重点空间生成效果图 prompt。Prompt 必须绑定户型分析、风格、预算档位和用户采纳的需求，避免生成泛化风格图。

### 5.5 效果图生成模块

为 2-3 个重点空间生成装修效果图。

效果图表达设计方向和空间氛围，不承诺严格几何还原、真实尺寸、施工可行性或家具精确摆放。

### 5.6 PDF Brief 导出模块

将结构化方案和效果图渲染成适合阅读和转发的 PDF。

PDF 要让业主能看懂，也要让设计师或装修公司能快速理解用户需求。

## 6. 技术架构

MVP 使用国产模型栈，不依赖 OpenAI API。

推荐技术栈：

- Web App：Next.js
- 后端 API：Node.js / Next.js API Routes
- 数据库：Postgres
- 文件存储：火山引擎 TOS 或兼容 S3 的对象存储
- 异步任务：Redis + BullMQ 或云队列
- 户型理解：豆包多模态 / 视觉理解模型
- 设计师 Agent 与方案文案：豆包文本或多模态模型
- 效果图生成：豆包 Seedream 系列
- PDF 生成：HTML 方案页 + Playwright / Chromium 渲染 PDF

推荐高层流程：

```text
上传户型图
-> 保存原图
-> 豆包视觉模型进行户型分析
-> 用户确认或修正
-> 输入风格、预算档位和自然语言需求
-> 设计师 Agent 追问与建议
-> 更新需求画像
-> 生成结构化设计方案
-> Seedream 生成重点空间效果图
-> 生成 PDF brief
```

## 7. 技术边界

MVP 明确不做以下高风险专业工具范围：

- CAD 级户型解析
- 施工图
- 水电图
- 精确报价
- 真实 3D 漫游
- 品牌级采购清单
- 设计师后台
- 装修公司线索分发

系统需要为后续能力预留扩展点：

- 将轻量户型理解替换为专业户型解析
- 增加可编辑的房间结构
- 增加真实 3D 重建
- 增加更细的预算估算
- 增加设计师协作
- 增加 PDF 之外的分享链接

## 8. 数据模型

核心实体：

- Project：项目状态、户型图、创建时间、当前步骤
- FloorPlanAnalysis：识别房间、空间关系、问题、置信度、用户修正
- PreferenceProfile：风格、预算档位、自然语言偏好、生活方式、硬性约束
- AgentConversation：追问、建议、回答、采纳或拒绝记录
- DesignPlan：整体策略、重点空间方案、材料、配色、预算取舍、注意事项
- RenderingAsset：重点空间、生成 prompt、图片地址、状态、重试信息
- BriefExport：PDF 状态、版本、文件地址、生成时间

## 9. 错误处理

产品需要在常见失败场景下不丢失用户已填写信息。

如果户型图不清晰，提示用户上传更清晰图片，或允许进入手动描述户型模式。

如果户型分析不确定，明确标注不确定项，并请用户确认。

如果用户不知道如何回答问题，Agent 给出推荐选项并解释取舍，让用户一键采纳或拒绝。

如果某个空间效果图生成失败，允许用户单独重试该空间。图文方案不应被阻断。

如果 PDF 生成失败，用户仍然可以查看方案，并重新尝试导出。

如果生成耗时较长，UI 展示分阶段进度：

- 分析户型
- 整理需求
- 创建设计策略
- 生成重点空间效果图
- 准备 PDF brief

## 10. MVP 验收标准

MVP 达标标准：

1. 用户可以在 5-10 分钟内完成完整流程。
2. 系统能从清晰户型图中识别主要空间，并标注不确定项。
3. Agent 追问不超过 12 个问题。
4. 追问内容明显围绕用户户型和需求。
5. 方案包含 2-3 个重点空间。
6. 默认包含客餐厅和主卧。
7. 第三个重点空间根据用户需求和户型上下文选择。
8. 每个重点空间都有一张效果图和一段小白能看懂的解释。
9. 预算档位影响设计取舍，但不伪装成精确报价。
10. PDF brief 可以直接发给设计师或装修公司沟通。
11. 户型分析、效果图或 PDF 生成失败时，不会清空用户已提供的信息。

## 11. 后续暂不决策

以下事项等 MVP 验证后再决定：

- 是否增加 PDF 之外的分享链接
- 是否支持参考图上传
- 是否支持可编辑的 2D 户型结构
- 是否增加真实 3D 重建
- 是否增加设计师或装修公司交接流程
- 是否按城市和面积做更细预算估算
