# 阶段切换交互优化设计

## 背景

当前项目的主流程按阶段推进：

1. 上传户型图
2. 户型分析
3. 风格预算
4. 设计师追问
5. 方案生成中
6. 方案完成

现状中，多个阶段完成后会直接执行前端跳转，用户几乎感知不到“当前阶段已结束、下一阶段即将开始”的过程。尤其是在“设计师追问”结束后，系统会直接进入“方案生成中”，缺少确认感；其余自动阶段切换也显得过于生硬。

本次优化目标是在不改动后端状态机的前提下，补齐阶段推进时的反馈节奏，让自动流转更顺滑，并为关键节点增加必要提示。

## 目标

- 为自动阶段切换增加统一的过渡提示与动画。
- 为“设计师追问 -> 方案生成中”增加确认提示，避免无感跳转。
- 保持现有项目状态流转与路由结构不变，优先改造前端跳转体验。
- 将多个分散的直接跳转入口收敛到统一的阶段跳转控制入口，降低后续扩展成本。

## 非目标

- 不重构后端项目状态机。
- 不引入用户手动切换阶段能力。
- 不拆分“方案生成中”内部子状态为多个独立步骤页。
- 不对无关页面样式做额外翻新。

## 用户问题

### 当前痛点

- 阶段完成后直接跳转，过程太突然，像“页面被刷新”而不是“流程在推进”。
- 用户无法明确感知当前阶段是否真的结束。
- “设计师追问”结束后直接开始方案生成，缺少一次明确确认，用户心理预期不足。

### 期望体验

- 普通自动流转应有明显但不打断的过渡提示。
- 关键节点应在进入下一阶段前先告知用户发生了什么。
- 整体体验应更像一个连续的产品流程，而不是一组割裂页面。

## 设计原则

- 轻量：过渡是辅助反馈，不应喧宾夺主。
- 一致：所有自动阶段推进都走统一入口。
- 可解释：每次跳转都能告诉用户“为什么现在要进入下一步”。
- 低侵入：优先复用现有页面与路由，避免大范围重构。

## 方案对比

### 方案 A：页面内拦截再跳转

在各个当前页面内，直接拦截原有跳转动作，先显示遮罩层或弹窗，再延迟跳转。

优点：

- 初始改动较小。
- 更贴近各页面已有实现。

缺点：

- 逻辑会分散在多个页面组件里。
- 后续新增阶段时，容易遗漏统一体验。
- 弹窗、动画、一次性状态判断会重复实现。

### 方案 B：独立过渡页承接自动流转

所有自动阶段推进都先进入一个统一过渡页，由该页决定展示自动过渡提示还是确认提示，再进入目标阶段。

优点：

- 动画、文案、跳转时机、一次性消费逻辑都能集中管理。
- 非常适合当前“多个直接 `window.location.assign(...)` 分散存在”的代码结构。
- 后续扩展更多阶段规则成本低。

缺点：

- 需要为“发起跳转时写入过渡上下文”和“过渡页消费上下文”建立一层新机制。
- 首次实现成本高于页面内零散拦截。

### 方案 C：全局跳转守卫

封装一个全局导航控制器，所有阶段跳转都必须经过这个控制器，它可直接在原页上显示提示，也可决定是否切换到过渡页。

优点：

- 长期最灵活。
- 很适合后面继续扩展复杂阶段流转。

缺点：

- 这次需求体量下偏重。
- 要同时处理当前页面覆盖层与路由切换协调，复杂度高于本次所需。

### 推荐方案

采用方案 B：独立过渡页承接自动流转。

原因：

- 能最稳定地统一当前项目里多处分散的自动跳转点。
- 能同时满足“普通阶段自动过渡”和“设计师追问结束后先确认”的双模式需求。
- 后续如果继续增加阶段提示、埋点或动画，只需维护一套逻辑。

## 总体方案

新增一个统一的“阶段过渡承接页”或等价的独立全屏过渡路由，所有自动推进先跳转到该承接页，再由承接页根据上下文决定：

- 直接展示自动过渡提示并延时进入目标阶段。
- 或先展示确认弹窗，用户确认后再播放短过渡并进入目标阶段。

该承接层只负责“阶段完成后的承接与推进”，不负责真正业务处理。项目状态仍由现有接口和后端流程驱动。

## 信息结构

### 过渡上下文

每次发起自动阶段推进时，前端应构造一次性过渡上下文，至少包含：

- 来源阶段 key
- 目标阶段 key
- 目标路径
- 过渡模式：`auto` 或 `confirm`
- 展示文案配置
- 一次性标识，防止重复消费

上下文应是临时态，只服务于当前这一次跳转，不应成为长期持久状态。

### 过渡模式

#### `auto`

用于普通自动流转。

行为：

- 进入过渡承接页。
- 显示“当前阶段已完成，正在进入下一阶段”的提示。
- 播放轻量动画。
- 约 `1200ms - 1800ms` 后自动进入目标路径。

#### `confirm`

仅用于“设计师追问 -> 方案生成中”。

行为：

- 进入过渡承接页。
- 先展示确认弹窗，不立刻跳转。
- 用户点击主按钮后，再切换到一个较短的自动过渡提示。
- 过渡提示结束后进入“方案生成中”。

## 触发规则

以下自动流转优先接入过渡承接页：

- 上传完成后进入“户型分析”
- 户型分析完成后进入“风格预算”
- 风格预算提交完成后进入“设计师追问”
- 设计师追问完成后进入“方案生成中”

其中：

- 前三类使用 `auto`
- “设计师追问 -> 方案生成中”使用 `confirm`

“方案生成中”页面内部若存在多个后台子状态变化，应继续留在同一页面中通过已有进度展示处理，不增加额外转场提示，避免频繁打断。

## 交互细节

### 普通过渡提示

页面中心展示一张状态卡片，包括：

- 完成态标题，例如“户型分析完成”
- 下一阶段提示，例如“正在进入风格与预算”
- 一条轻量进度动画或扫描线
- 辅助说明文案，解释系统正在做什么

体验要求：

- 用户不需要操作。
- 整体时长短，不造成等待焦虑。
- 文案应偏陪伴式，避免过重的系统警告感。

### 设计师追问结束确认

确认弹窗内容应强调：

- 当前追问已完成。
- 下一步将正式开始方案生成。
- 用户确认后才会进入生成流程。

建议交互：

- 主按钮：`开始生成方案`
- 次按钮：`再检查一下`

若用户选择“再检查一下”，则关闭确认态并返回追问页，不修改后端状态，也不提前进入生成流程。

## 文案建议

普通自动流转示例：

- `户型分析完成，正在进入风格与预算`
- `偏好已记录，正在进入设计师追问`
- `资料整理完成，正在准备下一阶段`

确认弹窗示例：

- 标题：`追问已完成`
- 说明：`设计师已完成本轮需求整理，下一步将开始生成方案。确认后进入方案生成阶段。`
- 主按钮：`开始生成方案`
- 次按钮：`再检查一下`

最终上线时允许文案微调，但语气应保持简洁、明确、陪伴式。

## 动画设计

动效目标是提升流程感，而不是制造炫技效果。

建议动画组合：

- 页面整体淡入
- 状态卡片轻微上浮
- 卡片背景光晕或呼吸感
- 横向进度线短距离扫过
- 标题、说明、辅助信息按 `80ms - 120ms` 节奏错峰出现

约束：

- 不使用厚重的全屏遮挡特效。
- 不使用夸张缩放、翻转等强装饰性动画。
- 动画应在桌面与移动端都保持稳定，不依赖高性能设备。

## 技术设计

### 跳转收口

当前代码中存在多处直接 `window.location.assign(...)` 或等价即时跳转。需要新增一个统一的阶段跳转入口，将这些自动推进逻辑改为：

1. 根据当前节点生成过渡上下文
2. 写入一次性过渡信息
3. 跳转到过渡承接页
4. 由过渡承接页消费上下文并决定后续动作

这套入口只服务于“自动阶段推进”，普通手动导航、刷新、返回等行为不应被误拦截。

### 过渡承接页职责

过渡承接页应负责：

- 读取一次性过渡上下文
- 校验上下文是否完整、是否过期、是否已消费
- 根据模式渲染 `auto` 或 `confirm`
- 在合适时机进入目标阶段
- 消费并清理一次性上下文，避免刷新重复触发

### 兼容现有生成页

“方案生成中”页面已有自己的轮询和状态展示逻辑。此次不改其内部节奏，只在进入该页面之前新增一次确认与短过渡。生成页内部的后台子状态更新仍留在原页内处理。

## 异常与边界

### 刷新行为

- 如果用户已经到达目标阶段，再刷新应直接看到目标阶段，不应再次播放过渡。
- 如果用户在过渡承接页刷新，且一次性上下文已消费或失效，应直接按安全策略落到目标阶段或来源阶段，避免死循环。

### 重复跳转信号

- 如果用户已经位于目标阶段，又收到重复推进信号，应忽略该信号，不再次展示过渡。

### 接口失败

- 如果发起自动推进前的接口调用失败，应留在当前页面显示原有错误态，不展示成功过渡提示。

### 用户取消确认

- 在“设计师追问 -> 方案生成中”的确认弹窗里点击“再检查一下”后，应回到追问页上下文，用户可继续查看内容或稍后再次触发。

### 无效上下文

- 如果过渡上下文缺失必要字段，承接页不应卡死。应采用保守回退策略，优先进入已有的 canonical 路由或当前安全页面。

## 可测试性

### 单元测试

补充以下测试：

- 不同阶段推进映射到正确的过渡模式
- 过渡上下文字段生成正确
- 无效上下文时的回退策略正确

### 集成 / E2E 测试

覆盖主流程中的关键断言：

- 风格预算提交后，不再直接瞬时进入追问页，而是先出现过渡提示
- 设计师追问完成后，不再直接进入生成页，而是先出现确认提示
- 点击“开始生成方案”后，进入短过渡，再进入“方案生成中”
- 点击“再检查一下”后，不进入生成页

## 实施建议

建议按以下顺序实现：

1. 抽出统一的自动阶段推进入口
2. 新增过渡承接页与一次性过渡上下文机制
3. 接入普通 `auto` 跳转
4. 单独接入“设计师追问 -> 方案生成中”的 `confirm` 模式
5. 补充单测与 E2E 断言
6. 统一打磨文案与动效细节

## 风险

- 当前跳转点较分散，若有遗漏，可能会出现部分流程仍然直接跳转。
- 过渡上下文如果没有设计成真正的一次性消费，刷新时容易重复展示提示。
- 如果确认逻辑与后端状态推进时机绑定不清，可能出现用户取消后状态却已经前进的问题。

为降低风险，实施时必须明确：“展示确认”与“真正开始下一阶段”的触发边界，确保用户取消时不会提前进入生成流程。

## 验收标准

- 普通自动阶段流转均先显示统一过渡提示，再进入目标阶段。
- “设计师追问 -> 方案生成中”必须先弹确认，再进入生成流程。
- 用户取消确认后仍停留在追问上下文，不会误进生成页。
- 页面刷新、重复信号、失败场景下不会出现无限跳转或重复提示。
- 动画体验自然、轻量，不显著拖慢主流程。
