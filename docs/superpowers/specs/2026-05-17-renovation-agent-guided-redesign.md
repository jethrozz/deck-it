# 装修设计 Agent UI 对齐版设计规格

## 1. 背景

当前项目已经有一张完整的目标 UI 参考图：`ui/ui.png`。这张图包含 9 个关键屏幕，从创建项目、上传户型图、户型分析、确认分析、风格预算、设计师追问、生成中、方案完成，到最终方案页。

本规格以该 UI 为准重新定义产品体验。核心方向保持不变：产品不再把上传、偏好、追问、生成和预览全部堆在同一个页面，而是改为分阶段向导。用户每次只完成一个任务，系统自动进入下一阶段。设计师追问阶段由 AI 设计师主动开场，提出空间想法、改造建议或生活需求问题，再根据用户回答继续推进。

## 2. 视觉参考

目标 UI：`ui/ui.png`。

该 UI 的产品气质是“专业、干净、轻科技感的 AI 设计师工作流”：

- 首页使用深色 hero，突出品牌感和 AI 设计师定位。
- 流程页使用浅色背景、居中白色画布、蓝色主按钮和顶部步骤进度。
- 页面主色为高饱和蓝色，辅以浅灰、白色和少量柔和图标色。
- 控件偏轻量，卡片圆角较小，整体应显得清爽、可信、专业。
- 最终方案页从向导式居中布局切换为报告式工作台布局：左侧导航，右侧方案内容。

实现时应优先复刻这张 UI 的信息结构、阶段顺序、视觉层级和关键文案风格。具体图片内容可以用真实生成结果或本地示意图替换，但页面结构应保持一致。

## 3. 页面与路由

采用“首页 + 项目向导 + 最终方案页”的路由结构：

- `/`：创建项目，对应 UI 1。
- `/projects/[projectId]/upload`：上传户型图，对应 UI 2。
- `/projects/[projectId]/analysis/loading`：户型分析中，对应 UI 3。
- `/projects/[projectId]/analysis`：确认户型分析，对应 UI 4。
- `/projects/[projectId]/preferences`：风格与预算，对应 UI 5。
- `/projects/[projectId]/interview`：设计师追问，对应 UI 6。
- `/projects/[projectId]/generating`：生成中，对应 UI 7。
- `/projects/[projectId]/complete`：方案生成完成过渡页，对应 UI 8。
- `/projects/[projectId]/brief`：最终方案页，对应 UI 9。

方案完成使用独立 `/complete` 路由，保留 UI 8 的完成反馈和结果入口。

每个项目页都应根据项目状态校验访问是否合法。如果用户刷新或直接访问某一步，系统应将用户带到当前应完成的阶段或最终方案页。

## 4. 全局向导布局

除首页和最终方案页外，向导阶段共享同一个基础布局：

- 顶部为 6 步进度条：上传户型图、户型分析、风格预算、设计师咨询、生成中、方案完成。
- 已完成步骤显示蓝色勾选状态。
- 当前步骤显示蓝色高亮。
- 未完成步骤显示浅灰状态。
- 主内容区域居中，使用白色卡片或大画布承载当前任务。
- 页面底部可有轻量提示，例如“预计需要 30-60 秒，请稍候”或“我们会自动识别房间、采光和空间关系”。

进度条中的“户型分析”覆盖 UI 3 的分析中和 UI 4 的确认分析两个状态。确认分析完成后再进入“风格预算”。

## 5. 屏幕规格

### 5.1 UI 1：创建项目

目标：建立项目并传达产品定位。

页面使用深色沉浸式 hero。左侧展示品牌和价值主张：

- 品牌：AI Design。
- 主标题：AI 设计师，让装修从想法到方案更简单。
- 辅助文案：为你整理需求、提供专业的设计建议和装修沟通 brief。
- 能力标签：户型分析、风格建议、方案生成、效果图、PDF brief。

右侧为“创建新项目”卡片：

- 项目名称输入框。
- 主按钮“开始创建”。
- 辅助说明：创建后可随时保存和继续。

提交后创建 Project，并跳转到上传户型图页。

### 5.2 UI 2：上传户型图

目标：让用户只关注上传户型图。

页面包含：

- 顶部步骤进度，当前步骤为“上传户型图”。
- 居中上传区域，支持点击选择或拖拽上传。
- 上传区域文案：上传户型图，支持 JPG/PNG 格式，建议上传清晰的户型图。
- 上传建议卡片：确保户型图清晰可见、包含尺寸或标注更准确、完整展示所有房间。
- 底部提示：我们会自动识别房间、采光和空间关系。

用户选择图片后，系统自动提交并进入分析中状态；页面不再额外要求用户点击“开始分析”。

### 5.3 UI 3：户型分析中

目标：让用户知道系统正在处理，而不是停在空白等待。

页面包含：

- 顶部步骤进度，当前步骤为“户型分析”。
- 中央图标和加载进度。
- 主文案：正在识别户型信息。
- 辅助文案：正在分析房间布局、采光和空间关系。
- 右侧分析任务列表：
  - 识别房间。
  - 分析采光。
  - 空间关系。
  - 动线分析。
  - 收纳分析。
- 底部提示预计时间：预计需要 30-60 秒，请稍候。

分析完成后自动跳转确认户型分析页。失败时保留上传结果，展示可重试入口。

### 5.4 UI 4：确认户型分析

目标：让用户确认 AI 是否看懂户型。

页面采用左右两栏：

- 左侧展示户型图。
- 右侧展示分析摘要。

分析摘要包括：

- 空间组成，例如识别到 3 室 2 厅 1 厨 2 卫 1 阳台。
- 采光分析，例如客厅和主卧采光较好，次卧采光一般。
- 动线分析，例如动线清晰，客餐厅通透性较好。
- 建议事项，例如玄关收纳空间不足、厨房操作台面较小。

底部提供一个补充输入框：

- 文案：以上分析准确吗？有需要补充或修改的地方吗？
- 用户可以输入修正内容。

主操作：

- 次按钮：跳过，确认无误。
- 主按钮：确认并继续。

确认后保存用户修正，进入风格与预算页。

### 5.5 UI 5：风格与预算

目标：收集用户的审美、预算和补充需求。

页面包含三块内容：

第一块：选择你喜欢的风格。

- 原木风。
- 中古风。
- 现代简约。
- 明亮通透。
- 侘寂风。

风格以图片卡片展示，选中态为蓝色描边。

第二块：选择预算档位。

- 经济型：10-15 万。
- 品质型：15-25 万。
- 高品质型：25 万以上。

预算以横向卡片展示，包含图标、名称和预算区间，选中态为蓝色描边。

第三块：补充你的需求和想法。

- 多行文本框。
- 提示用户补充生活习惯、喜欢的元素、功能需求等。
- 显示字数限制，例如 0/300。

主按钮：保存并继续。提交后进入设计师追问页。

### 5.6 UI 6：设计师追问

目标：让用户感觉自己正在和设计师咨询，而不是填写问卷。

页面采用三栏/两栏结合布局：

- 左侧主区域为对话。
- 右侧为项目摘要。
- 顶部保留步骤进度，当前步骤为“设计师咨询”。

进入页面后，系统自动请求 AI 设计师第一条发言，不需要用户点击“获取下一步问题”。

第一条发言必须由设计师主动开场，基于户型、风格、预算和用户输入提出空间想法或需求探索。例如：

> 我看这个户型有一个次卧空间。如果平时不常住人，可以考虑做成多功能书房，兼顾临时客房和收纳。你们对这个房间有什么明确需求吗？

也可以是更开放的需求探索：

> 关于餐厅的使用频率、是否有人同时使用厨房、需要更大的收纳空间吗？

交互规则：

- AI 设计师先问，用户再回答。
- 用户可以输入自由文本，也可以点击 AI 给出的快捷选项。
- 用户提交后，界面显示“设计师正在判断下一步”。
- 后端返回下一条设计师发言、建议采纳问题，或追问完成状态。
- 如果用户没有明确想法，AI 应给出 2-3 个专业方向供选择。
- 如果某个空间有改造机会，AI 应主动提出设计想法，例如次卧改多功能书房、阳台纳入客厅、玄关增加悬浮柜。
- 如果某个选择影响预算或落地风险，AI 应说明取舍并询问是否接受。
- 信息足够后，AI 总结将采用的方向，并自动进入生成中页面。

右侧项目摘要包括：

- 户型，例如 3 室 2 厅 1 厨 2 卫 1 阳台。
- 风格，例如现代简约。
- 预算，例如品质型 15-25 万。
- 已确认需求，例如增加书房功能、需要儿童活动区、偏好浅色系。
- 追问进度，例如 3/12。

追问最多 12 轮，但不强行问满。

### 5.7 UI 7：生成中

目标：自动完成方案、效果图和 PDF brief 的生成，让用户感知进度。

页面分左右两栏：

- 左侧为任务列表。
- 右侧为当前生成预览图。

任务列表包含 5 步：

- 整理需求画像。
- 生成整体设计策略。
- 生成重点空间方案。
- 生成效果图。
- 生成 PDF brief。

每个任务有状态：

- 完成：绿色完成态。
- 进行中：蓝色进行态。
- 等待中：灰色等待态。
- 失败：红色失败态并提供重试。

右侧展示当前正在生成的重点空间或效果图预览。页面文案应说明正在生成哪个空间方案和预计剩余时间。

用户不需要点击“生成方案”“生成效果图”“生成 PDF”。系统自动串联执行。全部完成后进入方案完成过渡页。

### 5.8 UI 8：方案完成

目标：给用户一个明确的完成反馈，并提供进入最终结果的入口。

页面包含：

- 标题：方案已生成完成。
- 辅助文案：你的专属设计方案已准备就绪。
- 左侧成果清单：
  - 设计方案：空间规划和布局建议。
  - 效果图：重点空间效果展示。
  - PDF brief：可下载的沟通 brief。
- 每项有“查看”入口。
- 右侧展示一张主要效果图。
- 主按钮：下载 PDF brief。
- 次级操作：重新生成效果图、重新进入追问。

完成页是独立阶段。进入该页后，用户可以下载 PDF brief、查看成果项，也可以进入最终方案页继续阅读完整 brief。

### 5.9 UI 9：最终方案页

目标：成为项目的长期结果页，像一份可阅读的设计 brief，而不是后台数据面板。

页面布局：

- 左侧为项目内导航。
- 右侧为方案内容。

左侧导航包括：

- 项目概览。
- 方案概览。
- 户型分析。
- 需求摘要。
- 重点空间。
- 风险与边界。

顶部区域显示：

- 项目名。
- 当前风格和预算档位，例如现代简约、品质型 15-25 万。
- 下载 PDF brief。
- 重新生成。

内容区域包括：

- 方案概览：一句话设计方向，以及 3-5 条关键策略。
- 户型分析：空间组成、采光、动线、问题点。
- 需求摘要：用户偏好、生活方式、已采纳建议。
- 重点空间方案：以 tab 或分区展示客厅、主卧、次卧/书房、厨房、卫生间等。每个空间包含效果图、设计目标、布局建议、材质配色、家具软装、预算取舍和落地注意事项。
- 风险与边界：明确该方案是装修前沟通 brief，不是施工图、正式报价或施工承诺。

最终方案页不得展示原始 JSON。

## 6. 状态与自动跳转

项目状态用于驱动路由和顶部步骤进度。

推荐状态流：

```text
CREATED
-> FLOOR_PLAN_UPLOADING
-> FLOOR_PLAN_ANALYZING
-> FLOOR_PLAN_ANALYZED
-> ANALYSIS_CONFIRMED
-> PREFERENCES_COLLECTED
-> INTERVIEWING
-> INTERVIEW_COMPLETE
-> GENERATING_REQUIREMENT_PROFILE
-> GENERATING_PLAN
-> PLAN_READY
-> GENERATING_RENDERINGS
-> RENDERINGS_READY
-> GENERATING_BRIEF
-> BRIEF_READY
```

最小实现可以复用现有状态，但需要提供一个统一的 `getProjectStep(project)` 映射，将项目状态映射到 UI 步骤：

- 上传户型图。
- 户型分析。
- 风格预算。
- 设计师咨询。
- 生成中。
- 方案完成。

每个页面加载时都应根据该映射检查当前路由。如果项目已经超过当前阶段，应跳到下一阶段或最终方案页；如果项目尚未到达当前阶段，应跳回当前应完成的阶段。

## 7. 数据与 API 行为

现有 API 可以继续作为基础，但需要按 UI 流程调整调用方式。

### 7.1 创建项目

`POST /api/projects`

- 创建 Project。
- 返回项目 ID 或直接重定向到 `/projects/[projectId]/upload`。

### 7.2 上传与分析户型

`POST /api/projects/[projectId]/floor-plan`

- 接收图片。
- 保存图片。
- 调用户型分析。
- 将项目状态推进到 `FLOOR_PLAN_ANALYZED`。
- 前端在上传页显示分析中状态，完成后跳转确认分析页。

### 7.3 确认户型分析

新增或扩展：

`POST /api/projects/[projectId]/analysis`

- 保存用户确认状态。
- 保存用户补充或修正内容。
- 将项目状态推进到 `ANALYSIS_CONFIRMED`。

### 7.4 保存风格预算

`POST /api/projects/[projectId]/preferences`

- 保存风格、预算档位和自然语言需求。
- 将项目状态推进到 `INTERVIEWING`。

### 7.5 设计师追问

`POST /api/projects/[projectId]/agent/respond`

请求支持两类动作：

- `action: "start"`：进入追问页时自动获取设计师开场。
- `action: "answer"`：用户提交回答后获取下一条设计师发言或完成状态。

推荐响应结构：

```ts
type AgentInterviewResponse =
  | {
      type: "designer_prompt";
      message: string;
      options?: string[];
      recommendation?: string;
      progress: { current: number; max: number };
    }
  | {
      type: "suggestion";
      message: string;
      options: ["采纳", "不采纳", "再解释一下"] | string[];
      progress: { current: number; max: number };
    }
  | {
      type: "complete";
      summary: string;
      nextPath: string;
    };
```

完成时项目状态进入 `INTERVIEW_COMPLETE`，前端自动跳转 `/generating`。

### 7.6 自动生成

推荐新增：

`POST /api/projects/[projectId]/generate`

该接口负责串联需求画像、设计方案、效果图和 PDF brief。前端只调用这个编排接口，并根据返回的任务状态更新生成中页面；用户界面不得要求用户手动逐个点击生成。

## 8. 组件边界

建议拆分现有 `ProjectWorkspace`，按目标 UI 建立更清晰的页面和组件边界。

页面级组件：

- `HomeCreateProjectPage`
- `UploadPage`
- `AnalysisLoadingPage`
- `AnalysisReviewPage`
- `PreferencesPage`
- `InterviewPage`
- `GeneratingPage`
- `CompletePage`
- `BriefPage`

共享组件：

- `WizardShell`：向导页外壳，包含最大宽度、背景、内容容器。
- `StepProgress`：6 步顶部进度。
- `PrimaryButton`、`SecondaryButton`：统一按钮样式。
- `StatusTaskList`：生成和分析任务列表。
- `StyleCard`：风格图片卡片。
- `BudgetCard`：预算档位卡片。
- `ChatMessage`：设计师和用户对话气泡。
- `ProjectSummaryPanel`：追问页右侧摘要。
- `BriefSidebar`：最终方案页左侧导航。
- `SpacePlanSection`：重点空间方案展示。

数据应由数据库持久化。页面组件只维护当前页面交互状态，不再用一个巨大的客户端状态对象承载所有阶段。

## 9. 文案与内容规则

- 面向业主，不使用专业黑话堆叠。
- 设计师发言应先给判断或想法，再提问。
- 设计师可以主动提出改造可能性，例如多功能书房、阳台纳入客厅、玄关收纳优化。
- 如果用户没有明确需求，设计师应给可选方向，而不是让用户继续空想。
- 预算只做档位约束和取舍说明，不输出精确报价。
- 效果图只表达设计方向和空间氛围，不承诺严格几何还原。
- PDF brief 是装修前沟通材料，不是施工图或正式合同附件。

## 10. 错误处理

- 上传失败：留在上传页，允许重新选择图片。
- 分析失败：显示失败原因和重试入口。
- 分析不确定：在确认分析页明确标注，不自动跳过。
- 偏好保存失败：保留已输入内容。
- 追问失败：保留对话历史，允许重试上一次提交。
- 生成失败：生成页定位失败步骤，允许只重试失败步骤。
- PDF 生成失败：最终方案页仍可展示网页方案，并提供重新生成 PDF。

## 11. 测试范围

需要覆盖以下行为：

- 首页创建项目后进入上传页。
- 上传户型图后出现分析中状态。
- 分析完成后进入确认户型分析页。
- 确认分析后进入风格预算页。
- 风格和预算卡片可以选中并保存。
- 保存偏好后进入设计师追问页。
- 追问页加载时自动出现设计师开场。
- 用户回答后自动追加下一条设计师发言。
- Agent 完成后自动进入生成中页面。
- 生成任务按步骤更新状态。
- 生成完成后展示方案完成页或完成态。
- 用户可以进入最终方案页。
- 最终方案页展示业主可读的方案内容，不展示原始 JSON。

## 12. 非目标

本次 UI 对齐重设计不包含：

- CAD 级户型编辑。
- 手动绘制施工图、水电图。
- 精确报价或采购清单。
- 真实 3D 漫游。
- 设计师后台。
- 用户账号体系。
- 支付或商业化流程。
